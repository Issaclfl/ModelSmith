# 数模论文写作风格规范（命题人范式）

> 依据：《数学建模及其应用》讲评专栏的命题人范文与同刊优秀论文——
> 命题人亲自示范的"标准答案写法"。本文件是论文写作的**最高规范**，逐条遵循。
> 程序化审计与本文规则同口径：`scripts/audit/audit_full.py` 的
> LogicAuditor/LanguageAuditor 会按本文件检查结构要素与 AI 痕迹。

## 一、结构范式：模型导向，而非问题导向

```
1 问题的提出          ← 精炼重述背景 + 加粗"问题N"列表（不照抄题目）
2 运动模型            ← 所有问题共用的基础模型，一次建完
3 核心机理模型        ← 题目特有的核心模型（如遮蔽判定、光学效率）
4 关键量的算法        ← 把数值算法精确化（min/max 定义式 + 分步伪代码）
5 问题1 的情形        ← 各问题只写自己特有的优化模型与求解
6 问题2 的情形
7 问题3 的情形
N 灵敏度分析 / 评价   ← 收尾
```

**反面清单**（常见低分写法）：
- 每个问题里重复推导同一套运动方程——共享推导只出现一次
- 独立的"模型假设"章节罗列 5-8 条——假设在用到的地方随文叙述
- "问题分析"单独成章写"技术路线图"——分析融入模型建立
- 摘要之后第 3 页才出现第一个公式——公式要早

**假设叙述规则**（范式与审计的交汇点）：
- 假设随文叙述，不设独立章节；但叙述时**必须出现显式假设词**
  （"假设/假定/不计/忽略/理想化"），如"忽略镜面间二次反射，能量只经一次反射到达集热器"
- 审计器靠这些词判定论文是否交代了建模前提——通篇没有假设词 = 结构缺口（会扣分）

**篇幅控制**：
| 章节 | 篇幅 |
|------|------|
| 问题的提出 | ≤1 页（约 300-400 字，背景 2-3 段 + 各子问题各 1 段） |
| 模型建立 | 核心章节，每个子问题 3-5 页，公式密集 |
| 灵敏度分析 | 1-2 页 |
| 模型评价 | 0.5 页 |
| 全文 | 8-12 页（不含参考文献） |

## 二、句式范式

| 场景 | 固定句式 | 范例 |
|------|----------|------|
| 引入变量/模型 | 记 … 为 …，则 [公式]。其中 … 为 … | 记 t 时刻导弹的位置为 P_m(t)，飞行速度为 v_m，则 … |
| 公式后解释 | 其中 A 为 …，B 为 …（逐符号，不允许无解释符号残留） | 其中 R_b 为太阳模糊盘半径，ρ_g 为偏移距离 |
| 优化前收缩 | 为了提高优化算法的计算速度，需要缩小决策变量的范围。 | 逐变量推物理紧界（如 t_b ≤ √(2z⁰/g)，理由：太晚烟幕落地） |
| 算法步骤 | 第1步 … (1)(2)(3) 子步骤 + 状态更新 + 转步条件 | 若烟幕能遮蔽目标，则 T=min{T,t}，t₂=t，转 (2) |
| 时间节点定义 | min/max 集合式 | T_s^top = min{ t \| max_θ d(P_s,P_c) ≤ r_s } |
| 结论生成方式 | 构造正面对比，由模型裁决 | 并非先验否定变尺寸设计，而是构造对比由全量模型裁决 |
| 结果落盘 | 结果已按模板写入 resultN.xlsx | 与竞赛提交要求呼应 |

## 三、摘要纪律（硬指标）

**总原则：摘要是讲理，不是报账。** 评委读完必须知道"你为什么这么算、为什么这个数对"，
而不只是"你算了"。三种病症出现任意一种即不合格（2025 风电篇摘要实证）：
- **只有结果没有理由**：报"年发电量 1115.4 GWh"，却不报用了什么模型、为什么可信
- **约束是黑话**："在几何紧界约束下"——评委不知道"紧界"是什么、值多少
- **决策缺推导**："推荐 35 台方案"——为什么 35？淘汰了谁？代价是什么？

对照正面示范（FAST 篇问题1句，准则+推理+结果一句话闭环）："令工作抛物面与基准球面
相交于 300 m 口径圆……191 个节点需求超程被截断，面形最大偏差 5.2 cm"——约束值 →
截断决策 → 代价明示。

### 3.1 每问一段，黄金三句式

开篇一句点题（本文针对【XX问题】，建立【XX模型】），随后**每个问题一段**，段内三句：

- **句1（方法句，30-40字）**：针对问题X，建立 [模型A+模型B] 的 [串联/递进] 模型链，
  核心是 [一句话亮点]。模型/方法名**加粗**（如 **Jensen 尾流模型**、**遗传算法**）
- **句2（约束决策句，40-60字，必填不许空）**：在 [约束名=具体数值] 的硬约束下，
  [原方案] 因 [量化的不可行原因] 被排除，采用 [最终方案]，实现 [关键权衡]
- **句3（结果句，30-50字）**：得到 [核心数字+单位]，较 [基准] 提升/降低 [百分比]，
  验证了 [物理/工程含义]

三句缺一不可：句1塌陷=方法来路不明，句2塌陷=决策没有理由（报账体的病根），句3塌陷=没有交付。

### 3.2 约束句模板（摘要最值钱的 30 个字）

> 在 [约束名]=[具体数值] 的硬约束下，[原本想用的方案] 因 [违反约束的具体表现/数值]
> 而不可行，故改用 [实际方案]，代价是 [量化代价]，收益是 [量化收益]。

写哪条约束，三条筛选规则：
1. 写**塑造了答案**的约束——没有它解会长得完全不同的那种（如 ±0.6 m 行程、3600 m 边界）
2. 写**淘汰了竞争候选**的约束——评委最想看排除逻辑（如 7D 等距方阵跨度 5740 m
   超出可用边界近六成被排除）
3. **删**人人都会写的约束（非负/整数约束之类）——写了反而暴露不自信

每段 1-2 条约束：多了变成约束清单，少了像没考虑约束。

### 3.3 现场改写示范（报账体 → 讲理体）

原文（问题2段，报账体）："针对问题2，在几何紧界约束下同口径对比方形、交错与长条候选族，
最优布局年发电量提升12.8%至1258.5 GWh，尾流损失降至11.5%。"

改写（三句式）："针对问题2，以 **Jensen 尾流模型**为目标函数，建立覆盖形态-朝向-间距-
交错四维的候选生成器与坐标级模式搜索的两级优化架构。在可用跨度 3600 m 与最小间距
2D=328 m 的硬约束下，7D 等距方阵（跨度 5740 m）因超出边界 60% 被排除，5×8 长条因横向
间距压缩至 212 m 被剔除，最终在交错网格种子上通过 4801 次模式搜索收敛至最优布局。
年发电量 1258.5 GWh，较给定布局提升 12.8%，尾流损失自 21.6% 降至 11.5%，验证了交错
布点沿主导风向拉开间距的核心策略。"

### 3.4 硬性自查（交稿前逐项过）

- [ ] 每句都有具体数字或具体模型名，无"较好""显著"等虚词
- [ ] 每问段都有至少一条约束+决策推导（句2 必填）
- [ ] 各问段之间有逻辑递进（前一问结果作为后一问输入等）
- [ ] 最后一句回应题目原始问题的现实意义
- [ ] 总字数 400-600 字，不超过一页；末行单独"关键词：3-5 个"
- [ ] 摘要中的数值只能来自代码真实输出，严禁编造
- [ ] 禁止变量符号（t、θ、v）与公式编号引用；模型名用文字+加粗，最终数值处可带单位

## 四、排版规范（对齐《数学建模及其应用》/国赛优秀论文）

- 节编号阿拉伯数字（1、2、3），节标题居中黑体；子节 1.1/3.2 左对齐
- 正文宋体小四、首行缩进 2 字符、两端对齐、公式全局连续编号 (1)(2)…
- 独立公式由编译系统统一编号，正文不手写式号，引用时用"上式""前述公式"
- 表：booktabs 三线表，表题上方居中不加粗，宽表内容缩字号
- 图：图题下方居中不加粗，宽度约半版心；每个子问题至少 1-2 张图表
- 参考文献 GB/T 7714-2015，中文文献在前英文在后，条目悬挂缩进

## 五、内容纪律（从命题人讲评提炼）

1. 遮蔽/覆盖类判定要交代判别法的**选择理由**（解析 vs 离散采样 vs 逐点），并说明为何其他做法有误差
2. 优化求解必须给出**超参数的具体数值**（种群、迭代次数、步长），只写"采用遗传算法"不得分
3. 多对象协同问题（多枚干扰弹并集遮蔽）不得简单相加各对象单独贡献——要处理重叠
4. 传统优化易陷零梯度初值，要说明初值策略或改用全局算法
5. 能解析的判定（二次方程判别式、夹角判别）优先于离散采样——采样使目标函数阶梯化，梯度法失效
6. **数值验算链条**：公式 → 代码实测中间值 → 与理论/题目已知对比。所有数值只能引用
   脚本真实打印的输出，**严禁自行手算新数字**填充验算过程——你手算的数值不可信
7. **多模型对比**：问题允许多种算法时，必须对比至少 2-3 种（统一数据集与指标），说明最终选择理由
8. **灵敏度分析**：选 2-3 个直接影响结果的关键参数扰动 ±10%~±20%（不要选算法超参数）；
   算法稳定性用独立运行 10 次的标准差说明；两种独立方法交叉验证偏差 <0.5%
9. **灵敏度反编造铁律**：没做过扰动实验就严禁编造扰动数值——只能定性机理分析，并如实说明
10. **评价章**：优点 4 点 / 缺点 4 点 / 改进方向 4 点（针对每个缺点），可附可解释性分析
    （事前/过程/事后，如 SHAP、t-SNE）
11. **优劣结论必须带边际声明**：凡"方案 A 优于方案 B"类结论，写明优势量（数值）并与
    论文已披露的残差/误差带对照——边际小于误差带时不得写"显著优于/全面优于"，
    只能写"在误差范围内两者不可分"或如实降级表述（对应 DISCIPLINE 五.7）

## 六、人类写作风格（★ 核心反检测规则，每一条都必须遵守 ★）

你写的每一句话都要像一个真实参赛队员在截止前熬夜写出来的——有紧迫感、有口语化痕迹、偶尔不那么"完美"。
AIGC 检测器测量的是**写作模式的统计规律性**（词频分布、句长方差、句式重复率），不是内容正确性。
你的目标是打破模式规律性，同时保留所有事实、数据和逻辑论证。

### 6.1 禁止的 AI 句式壳（出现任何一个都扣分）

- 1.1 **二元对比壳**：❌"不是 A，而是 B""与其说 A，不如说 B"→ 删除 A 铺垫直接陈述 B
- 1.2 **阶段序列壳**：❌"先 A，再 B""从 A 到 B"（抽象概念）→ 用实际动作/因果替代仪式化排序
- 1.3 **本质宣称壳**：❌"真正重要的是""本质上""核心在于""底层逻辑"→ 直接说出具体主体
- 1.4 **助手路标**：❌"值得注意的是""总的来说""不可否认的是""在这个过程中"→ 直接进入实质内容
- 1.5 **收窄框**：❌"这个问题很简单：""这次只看…"→ 删除铺垫直接给证据
- 1.6 **无动机结尾问句**：❌"你觉得呢？"→ 删除

### 6.2 高频词频率硬限制（超出即判为 AI）

| 词 | 上限 | 轮换词 |
|----|------|--------|
| 本文 | ≤15 | 该模型 / 所建模型 / 上述方法 / 所提方法 |
| 采用 | ≤5 | 运用 / 选用 / 借助 / 依靠 |
| 通过 | ≤5 | 借助 / 依靠 / 凭借 / 经由 |
| 基于 | ≤3 | 鉴于 / 以…为基础 / 从…出发 |
| 构建 | ≤3 | 搭建 / 建立 / 设计 |
| 实现 | ≤3 | 做到 / 完成 / 达到 |
| 此外、另外 | 合计 ≤3 | 与此同时 / 进一步来看 |
| 分析结果表明 | ≤2 | 从结果来看 / 数据显示 / 计算结果说明 |

### 6.3 句式节奏（Burstiness）

1. **句长极差 ≥20 字**：至少一个短句（≤8 字）和一个长句（≥30 字）
2. **中段不扎堆**：连续 3 句字数差 ≤5 字 → 打破其中一句
3. **每 3-4 句插入一个短句**："这是关键。""问题就在这里。"
4. **段落长度不均**：有的 2-3 行，有的 6-8 行——严禁每段都 5-6 行
5. 偶尔一句话独立成段（强调效果）

### 6.4 RLHF 痕迹去除（助手腔全部清除）

- ❌ 平衡式权衡："一方面 X，另一方面 Y，需要综合考虑" → 直接给结论
- ❌ 教学式铺垫："所谓 X，是指…"（读者是评委）
- ❌ 结尾总结重述："综上所述，本文…" → 用最后一个实质句结尾
- ❌ 礼貌性免责："当然，这只是初步探索" → 直接陈述局限
- ❌ 过度限定："在一定程度上""在某种意义上"（只在真正不确定时用）

### 6.5 段落开头多样化

- 每个子问题的小节开头用不同句式（"针对这一问题""考虑到xxx""从物理意义来看""当xxx时"…）
- ❌ 严禁连续两个子问题用相同开头模式
- ❌ 严禁每段都以"本问题要求…""其数学本质是…"开头

### 6.6 标点指纹

- 破折号"——"：每 300 字最多 1 个，全文 ≤5 个
- 分号"；"：全文 ≤3 个（用句号替代）
- 冒号"："：每段最多 1 个，且前面必须是完整句子

### 6.7 不确定性表达

- 全文至少 3 次（"可能""在合理范围内""可以认为"），但不要每句都加——过度限定本身也是 AI 特征

### 6.8 引用自然化

- 用"xxx等[1]""文献[1]指出"；引用位置不要全部紧跟名词
- ❌"本文采用遗传算法[3]进行求解" → ✅"求解阶段选用了遗传算法，该方法在高维连续优化中的表现已被广泛验证[3]"

## 七、全局铁律（优先于任何风格要求）

1. **禁止元评论**：全文严禁"设计思路""写作思路""我选择了…因为…"等对论文自身的解释
2. **禁止本地路径泄漏**：正文/表格/图注严禁出现 data/、figures/、C:\ 等路径；图片以"图N 描述"引用
3. **禁止占位符**："[请填入]""[待补充]""TODO"零容忍——审计器命中即硬红线不通过；数据缺失处写"—"
4. **数值唯一来源**：论文中每个数字来自脚本真实输出（可溯源），宁可少写不可编造
5. **标题一致性**：标题中出现的任务/方法必须与实际求解内容一致，严禁引入未求解的任务
