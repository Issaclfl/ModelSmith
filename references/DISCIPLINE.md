# 工作纪律（求解全流程强制项）

> 与 SKILL.md 五步工作流配套。每一条都来自实战踩坑（根因见 PITFALLS.md），
> 违反任意一条都曾直接导致结果错误、超时或论文返工。

## 一、审题确认单（任何计算之前强制填写）

```
物理场景确认单
- 运动主体1：位置___，速度___，方向___
- 运动主体2：位置___，速度___，方向___
- 两者的初始相对位置关系：同侧/同线/垂直/斜交？
- 坐标系定义：原点___，正方向___
- 约束条件：___
- 优化目标：最大化___？最小化___？
- 单位制：是否统一？
```

**常见跳读陷阱**（跳过确认单直接计算，结果有极大概率是错的）：
- "沿x轴运动"和"沿y轴运动"导致完全不同的公式
- "初始高度为h"和"初始高度为0"改变整个方程
- "有空气阻力"和"无空气阻力"适用不同模型
- "目标沿直线"和"目标沿圆弧"需要不同方法

## 二、数据探索确认单（题目含附件数据时强制）

```
数据探索确认单
- 数据维度：___行 × ___列
- 列含义：第1列___，第2列___
- 数值范围：min___，max___
- 是否有跳变/突变区域？位置___
- 是否有零值/缺失/异常值？比例___
- 是否有明显物理不合理的数据？___
- 建议使用的数据区间：___到___
- 排除的数据区间：___到___
- 排除理由：___
- 预处理步骤：___
```

**可信区间声明契约**——对每个数据文件，最终必须能写出这段 JSON（进论文的数据才算有据）：

```json
{
  "trusted_ranges": [
    {"file": "附件1.xlsx", "x_column": "波数",
     "keep": [1000, 4000], "exclude": [0, 1000],
     "reason": "低波数段为测量系统校准归零区"}
  ]
}
```

- 每个异常必须给出**物理解释**（范例："830 cm⁻¹ 处反射率突变是 SiC 材料吸收边的特征"）
- 超出传感器量程的数据必须排除
- **宁可少用数据，不可用错数据**

## 三、方法选择纪律

1. **先查 MODEL_PLAYBOOK.md 的题型→方法套路表**，复制最接近的 examples/ 范例脚本适配，不从零写
2. **白名单外的方法必须记录替换理由**（一句话写进论文的算法选择段），静默替换会让论文理由失真
3. **结构诊断红线**：任何枚举/搜索前先做维度与规模估计——2025A 实测教训：未估计维度直接
   对 streaming 维度网格搜索，直接爆时间。先估"搜索空间多大 × 单次评估多贵"，超预算先降维
4. **多模型对比 ≥2-3 种**：统一数据集与指标公平比较，最终选择要说明理由
5. 无成熟模板匹配时进**安全模式**：只输出公式推导和解题框架；必须写代码时只用标准库
   （numpy/scipy/sklearn），并标注"此部分数值待人工验证"
6. **问题重构（选型前强制）**：给出 ≥2 种问题表述/建模视角，选最锋利的一种并说明为何。
   评委眼里"眼前一亮"的高频来源不是算法本身，而是表述方式的选择（如"用对比布局裁决
   问题3"这类重构）
7. **专属判据（每题至少一个）**：从题目物理中推导一个专属的结构性结论——守恒量/不变量/
   紧上界/可命名准则——命名、单独验证、写进论文。这是与"教科书标准件组合"拉开档次的
   最低成本动作（范例：FAST 篇"边缘销接准则"）
8. **跨域工具扫描（交付前 5 分钟）**：检查图论/控制论/信号处理/统计物理/博弈论有无更
   锋利的既有视角；有则认真评估，无则一句话记录"已评估不适用"——防止答辩被问倒，
   也是跨界迁移得分点（如"图神经网络建模复杂系统"）的强制入口

## 四、单位一致性铁律

实测教训：逃生路径题 60 倍偏差 = 分钟当秒。

- 全程统一 SI 单位制，变量名显式标注单位（t_min / v_ms / dist_km）
- 每个时间类结果用 距离÷速度 独立复算量级，两者数量级必须一致
- 常识 sanity check：人步行 1km ≈ 10~15 分钟——算出 10 秒或 10 小时都是单位错误
- 论文中所有物理量必须带单位，禁止裸数字

## 五、代码自检协议（跑完必做）

1. **metrics.json 自声明物理区间**：脚本把关键指标写入 metrics.json，并附
   `_expected_ranges: {指标: [min, max]}`；执行后逐项核对。超出声明范围的常见原因：
   ① 公式/判定条件写反 ② 单位未换算（km/m、cm/m）③ 迭代发散或初值不当
   ④ 确认实际值正确则是声明范围不合理，修正声明
2. **强弱零键检查**：
   - 强零键（时长/遮蔽/覆盖/duration/shadow/coverage）：物理上几乎不可能为 0，
     任意一个为 0 = 几何判定/物理条件写反或坐标系错误，结果无意义
   - 弱零键（距离/区间/路径/收益）：全部为 0 才告警
3. **多种子稳定性（随机类算法必跑）**：`python scripts/solve/run_stability.py 脚本.py --runs 10`——
   max CV>0.5 结果不可信必须修复；>0.15 论文必须报告均值±标准差。种子由沙箱统一注入
   （random/numpy 双源），脚本内不要再自己设种子
4. **物理边界自检**：效率≤1、速度≤光速、长度非负、量纲一致
   （可用 `scripts/audit/audit_runner.py` 对论文快速复检）
5. **执行偷懒检测**：`python scripts/audit/laziness_check.py 你的脚本.py`
6. **沙箱执行**：`python scripts/solve/sandbox_run.py 求解脚本.py --algo <算法名>`——
   安全 AST 扫描（拦 eval/exec/dunder 逃逸/危险写文件）、按算法动态超时、
   隔离执行、"假装成功"检测（returncode=0 但无产出/SELFTEST FAIL ≠ 成功）一体化。
   **禁止用裸 shell 跑求解脚本**——上次没出事不是放行理由
7. **边际-残差核对（排序结论的杀伤半径）**：任何"A 优于 B/淘汰 B"的排序结论，优势边际
   必须大于该结论依赖链上的最大已披露残差/误差；边际小于残差带时结论必须降级为
   "在误差带内不可分"。实测教训：披露了 2% 深度残差，却没看穿它击穿"35 台同时优于
   36 台"的核心推荐——披露 ≠ 看穿

## 六、绝对禁止（6 条）

1. 禁止在未完成审题确认单（第一节）和数据探索确认单（第二节）的情况下进入计算
2. 禁止将全量数据无差别地喂入任何算法
3. 禁止套用经典公式而不检查适用条件
4. 禁止输出未经验证的数值结果
5. 禁止在数据明显异常时忽略不报
6. 禁止交付未附带 audit_full 完整审计报告的论文（**无报告 = 未交付**）


下次接到同类题，**先读 experience.md 再动工**——这是把一次教训变成永久纪律的唯一途径。

**晋升规则（防知识库腐败）**：同一个坑在 ≥2 次任务中复现，就从 experience.md 晋升进
技能包 `references/PITFALLS.md`（维护者操作）——experience.md 是候补池，PITFALLS 是
转正名单。晋升时合并同类项、删除已失效条目：知识库只沉淀不复述，停在过去的经验里
等于没有知识库。
